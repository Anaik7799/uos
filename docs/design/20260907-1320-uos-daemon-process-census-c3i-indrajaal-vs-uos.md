## Key architectural finding

`apps/cepaf_gleam/src/cepaf_gleam/uos_sup.gleam` — the module CLAUDE.md section 5.1 names as the root 4-domain OTP supervisor — is **purely declarative**. `start_root_supervisor()` creates an empty `static_supervisor` with zero children attached; the 11 child names in its `DomainSpec` lists (`cepaf_gleam_wisp`, `indrajaal_holon_runtime`, `indrajaal_web`, `zigvm_port_manager`, `hermes_oracle_supervisor`, `max_isolated_worker`, `mcp_unified_gateway`, `planning_worker`, `holon_swarm_mesh`, `lease_fencing_monitor`, `rete_ul_engine`) are string literals used only by `validate_spec/1`, a pure function that checks the *list has ≥8 entries* — it does not check that any of them exist as real code. A repo-wide grep for each identifier finds it nowhere else in the non-build source tree. Every daemon/listener that *is* actually running in UOS today (indrajaal_gleam_web on :4100, the Zenoh router, clock-guard) is started through an entirely separate path (systemd, direct `gleam run`, or a bash wrapper around an OCaml binary), never through this supervisor.
