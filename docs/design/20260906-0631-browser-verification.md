## Findings and measurement limits

The generated document JavaScript contained a literal newline inside a quoted split argument, preventing client code from parsing. The raw/rendered toggle was consequently undefined. The checklist dominated the first screen. Planning lacked shared structural elements. Some filters/buttons produced no DOM change. Many pages lacked exactly one H1, and controls overflowed narrow viewports.

HTTP status was an independent Curl GET because the installed binding lacks the Response.status accessor; it is not the exact browser-navigation response. The controller records generic DOM changes as `REQUIRES_SPECIFIC_EXPECTED_RESULT`. Hidden/disabled/effect-boundary controls are UNRUN. The baseline details-restoration helper aliased absent and empty `open` attributes, so that `restored` field is insufficient evidence. Later fixture checks use exact `[open]` counts.

The initial crawl had a 500-page quota and excluded query-bearing URLs, API/event endpoints, other origins and unsafe path shapes. It cannot establish all external links, query states, permission states or dynamically hidden destinations. Four viewport passes alone do not satisfy the complete semantic closed loop requested for every component.
