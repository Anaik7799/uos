## 6. Patterns & Anti-Patterns Discovered

**RR-01 — P1, global budget activation gate.** The SQLite component intentionally reports `budget_scope: this_database_only`, accepts a locator and returns `task_authority: false`. Its transaction/trigger design is useful within that database. The worker's paid policy does not itself consume a fresh reservation. Bind one canonical, fenced dispatch owner to one ledger and derive request metadata there; observe concurrent requests, stale attempts, duplicates, missing/corrupt storage and restart retention before claiming a system-wide $10/day cap. A field named `dispatch_authorized` in a component receipt must not be mistaken for task authorization.

**RR-02 — P1, legacy budget exclusion.** At the primary snapshot, `route.gleam:681–813` and `uos_route_cli.gleam:193–215` expose JSONL initialization and charging. Initialization overwrites previous totals; charging rereads an epoch, checks a sum, then appends without a lock or compare-and-swap. Two readers can both append the same next epoch and return success while the last line omits one charge. Negative charges are not rejected. Explicitly retire this path from paid authority and correct its atomicity language; retain historical evidence. Only the selection core should be called pure.

**RR-03 — P1, request binding; specific byte flaw source-repaired.** The initial grapheme-count limit did not bound UTF-8 bytes. The worker now checks 8192 actual bytes per system/user field, closing that source-level bypass. The ledger still receives caller-declared `input_bytes` and `body_bytes`. The owner must derive counts from the exact serialized body, enforce the 16384-byte input, 65536-byte body and 4096-token bounds, and bind model/tokens/body digest/call ID to a one-use grant. The 2048-token provider-template allowance and treatment of reasoning require evidence; the `/4` heuristic is not a hard liability bound.

**RR-04 — P1, learning gate.** `Posterior` is publicly constructible, and `update` accepts any nonempty evidence reference repeatedly. A string plus a Boolean does not authenticate a task/candidate/model/class-bound verification or prevent double counting. Keep prior weight separate from verified-trial counts, validate posterior invariants, and require accepted single-consumption receipts. A posterior mean and three trials do not establish a 90–95% reliability confidence bound. Initially unproven models need an explicit bounded calibration path; an API answer is not coding or decision quality.

**RR-05 — P1 finding source-repaired; final release evidence pending.** Initially `actual_cost` could replace missing provider cost with a catalog estimate and the worker did not reject excess output tokens. The reviewed follow-up now makes paid `run` reject absent reported cost, a mismatched reply model, output tokens above admission and reported cost above the requested/hard $0.25 bound. Those checks are wired into the returned outcome. The free adapter already separately requires reported zero cost and bounded output. Preserve the original failed condition and bind final candidate tests to the repair. A rejected response may already have incurred cost, so reservation liability must remain on failure or ambiguity.

**RR-06 — P2, documentation/provenance refresh.** Update the historical selected-model finding with the source/test repair receipt. The recommendation's paid roster, endpoint ceilings and reasoning statements are parent-observed metadata; this reviewer did not independently fetch them, and did not find the new durable catalog/endpoint receipt during the initial scoped search. Bind URL/time/bytes when publishing that claim. The other router is correctly classified as a catalog projection: `or_first` can pick an unrelated tier and `budget_approved` is always true in `build_decision`; it is not a dispatch authority. `run_routed` currently routes class R3 advisory, so coding-family profile labels do not establish R4 implementation calibration.

## 9. Architectural Observations

The proposed layering is appropriate: pure eligibility selection, one effectful OTP owner, an atomic durable liability interpreter, bounded HTTP execution and authenticated verification evidence. All actors may request services through that owner; giving every actor the ability to choose a database or synthesize a grant would defeat the aggregate limit.

Provider `max_price` serialization uses USD per million tokens, while the source catalog and OCaml arithmetic use per-token units. The staged worker's conversion and zero request-fee ceiling are consistent with that intended unit boundary. Endpoint price availability and mandatory-reasoning behavior still require bound public metadata and live invocation evidence at the chosen candidate. No model ranking follows from these unit checks.
