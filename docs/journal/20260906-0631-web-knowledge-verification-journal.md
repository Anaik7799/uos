## 4. Root Cause Analysis

Several apparent verification successes measured declarations rather than behavior: counters copied into passed totals, booleans standing in for algebraic laws, digest equality standing in for independently executed oracles, and HTML-string assertions standing in for browser actions. Some documentation converted synthetic metrics and historical counts into broad admission claims.

The actual document renderer emitted an invalid JavaScript newline literal from a Gleam string. Once fixed, responsive layout and menu discoverability defects became observable. The browser experiments show why compilation, semantic interaction and visual inspection are separate checks.

Actor/model inspection exposed a similar distinction: representable FPP records and printable Zenoh messages do not establish active processes or remote delivery. A local publish result does not prove consumer commitment. TCM terminology, a four-field “13D” check, label-only denotation and unit-valued SysML constructors are specific specification/implementation gaps.

## 6. Patterns & Anti-Patterns Discovered

Useful patterns include pure algebras with independent observations, negative compiler checks, SAT controls, original-source digest comparison, typed browser locators, per-control state restoration, and repeated visual/semantic feedback. Harness-Bionic's single-writer/auditor separation and ZigVM's transport-independent envelope provide useful design references.

Anti-patterns include tautological properties, simulated browser passes, source counts labeled test coverage, unexplained missing/skipped live legs, unpinned remote Markdown execution, whole-document hashes presented as sheaf gluing, constant “measurements”, shell transport failures discarded, and acknowledgment inferred from publication alone. Audit source comments against the code that actually executes.

## 9. Architectural Observations

UOS needs explicit correspondence between intent, pure semantics, authorized effects, models, actor messages, receipts and UI state. The Gleam compiler supplies useful type guarantees but does not prove arbitrary value-dependent laws. Hermes provides bounded analysis; actual runtime and browser observations supply the independent behavior key.

The actor ecology should reuse existing MoZ session state and supervisors where verified. It must separate commands, queries and telemetry; distinguish publication, delivery, application and durable commitment; and prevent observer-to-writer authority escalation. FPP and SysML have complete conformance programmes, with partial projections represented honestly during implementation.

The final operator addition mandates the C3I Zenoh NIF and Zenoh for all UOS application/domain communication. Two inspected C3I/UOS native source files already match byte-for-byte, but wrapper stubs, split MoZ/direct-NIF call paths, unloaded-get success, singleton replacement and blocking-lock concerns remain. The unified prompt and plan now require native symbol/loading checks, complete pub/sub/query/queryable lifecycles, bounded scheduling and an exhaustive communication-edge migration matrix. This review did not claim native integration complete.

The subsequent operator addition requires the richest correct and measured native baseline plus complete Zenoh feature coverage. Targeted read-only comparison found three native candidates: current C3I/UOS (five exports), legacy Indrajaal (17 including three policy helpers), and Gleam/Sutra (six). Legacy Indrajaal exposes the broadest inspected native surface but has empty-Put delete, no-op explicit close, hardcoded status, ignored callback PID and allocation-bound concerns. Sutra source was located under sutra_server; inspected positive-test examples also accept errors. Four legacy benchmark suites measure PubSub, mocks, serialization or simulated publishing, so they cannot establish native performance leadership. The prompt and plan now require full versioned API/feature/profile coverage and controlled receipt-based benchmarks. No external code or binary was executed or admitted.

The handover's ten-axis analysis can organize requirements, but mathematical names require real carriers and laws. A full atlas needs L0–L9 implementation and evidence links, not ten headings.
