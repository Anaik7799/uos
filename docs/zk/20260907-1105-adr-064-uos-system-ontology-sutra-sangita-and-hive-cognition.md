## Context

The Unified Operational System (UOS) hive mind requires a unified conceptual framework that grounds cognition, communication, and control in three ancient knowledge traditions: Hindu philosophy (Sāṃkhya, Vedānta, Yoga Sūtra), the Bhagavad Gītā's ethical and functional principles, and the Hindustani musical system's seven thaats and rāgas as organizational metaphors for seven computational planes.

Per operator directives:
1. "Create full system ontology, dictionary, glossary and wiki, zk and km covering all fractal aspects of the system."
2. "Maximize the use of sutras in the system for communication in the system."
3. "Use Indian Hindustani musical system for musical building blocks, Hindu thinking structures thinking and memory structures, use gita as much as possible for higher-order thinking."
4. "Allow hive to think, dream and evolve."

Round O (September 7, 2026, workers O-1 through O-6) unified the system's ontology across:
- **Ontology Module**: 226 concepts in 15 domains, including antaḥkaraṇa (inner instrument), pramāṇa (means of valid knowledge), citta-vṛtti (mind modifications), pañca-kośa (five sheaths), guṇa (three qualities), and 33 holons in 7 planes.
- **Sūtra Register**: 49 sūtras (7 per pāda, mirroring the seven planes), 6 with classical Yoga Sūtra and Gītā citations, validated on the board as ACL utterances.
- **Gītā Register**: 27 Bhagavad Gītā verses grounding control actions, ethical authority, and knowledge structures.
- **Hindustani Music Mapping**: 10 thaats ↔ 10 layers (L0–L9), 10 rāgas ↔ 10 modes, 6 tālas (Teentaal as audit heartbeat).
- **Holon Base Rules (B1–B9)**: Verified PASS across 33 holons; dharma and swara assigned per holon.
- **Dream & Evolve Loops**: Idle-only svapna (hypothesis generation), Thompson-sampling-driven evolution with Beta fitness, three hypothesis kinds.
- **Cost Routing (R0–R6)**: Deterministic → verification → summaries → advisory → implementation → sovereign review → design authority.
- **Saṅgīta Module** (in progress): Teentaal as sam/khālī/tālī reference frame; pure-Gleam 16-bit WAV; just-intonation swaras; board harmonization.

## Decision

The UOS hive mind SHALL adopt the unified system ontology and all Round O components as the canonical foundation for coordination, knowledge management, control plane semantics, and agent cognition. The decision spans seven subsections:

### Ontology

The **system ontology** (226 concepts in 15 domains) serves as the authoritative semantic namespace for:
1. **Coordination**: Leases, epochs, fencing tokens, heartbeats, line-stop (jidoka), andon signals, muda labels.
2. **Messaging**: 14 board message kinds (Plan, Dispatch, Claim, Progress, Question, Answer, Report, Verdict, Andon, Jidoka, Integrate, Heartbeat, Intent, DeadLetter, …), 12 performative acts (Inform, Request, Propose, Accept, Reject, Query, Confirm, Commit, Assert, Retract, Hypothesize, Andon), 8 board muda types.
3. **Structure**: 7 planes (control, structure, runtime, data, messaging, intelligence, language), 33 holons from uos (root) to individual F´ ports.
4. **Intelligence**: Memory (working, episodic, belief, goal), capabilities (Memory, Rete, Bayes, Zenoh, Lean, Quint, STM), 6 OODA modes (Dark, Dim, Normal, Bright, Emergency, plus Idle).
5. **Thinking & Memory**: Antaḥkaraṇa (manas, buddhi, ahaṃkāra, citta), four pramāṇa (pratyakṣa, anumāna, śabda, upamāna), five citta-vṛtti (pramāṇa, viparyaya, vikalpa, nidrā, smṛti), five kośa (annamaya, prāṇamaya, manomaya, vijñānamaya, ānandamaya).
6. **TUI/Library**: 40 UI primitives (App, Screen, Widget, etc.) mapped through fidelity ladder (Deferred → Reinterpreted → Homomorphic → Isomorphic).

**Validation**: `uos_swarm holon.gleam holarchy` contains all 33 holons; `board.gleam validate_semantics` resolves through ontology; CLI `ontology dictionary|glossary|wiki|json|check|resolve` operationally grounded.

### Sūtra and Gītā

The **49 sūtras** (7 per pāda, one pāda per plane) encode the distributed control laws and operating principles:
- **Pāda 1** (Control Plane): Intent goes upward only; messages are sender-signed; leases bind to monotonic epochs; coordinators seed from durable log; unknown health is andon (not silent green).
- **Pāda 2** (Structure): Design kinds come only from design authority; every part like the whole (holarchy); holarchy is acyclic; declared proof is not admissible (S2.4, from BG 2.47); checklists are evaluated item-by-item.
- **Pāda 3** (Runtime): Cost of runtime control is 0 tokens; OODA cycle is bound to fixed budget; reconcile failure → andon on next cycle; first authorization refusal stops posting.
- **Pāda 4** (Data): Per-sender chains append-only; lost message replies need causal-gap records; delivery tracked via transactional outbox; memory grant-gated; capability grants expire; shared key never deleted.
- **Pāda 5** (Messaging): Routing decisions are board messages; free tier tried first (≤ USD 0.02 floor); prompts sanitized before external tiers; no ACK alone grants authority; dead-man's-switch marks silence as stale.
- **Pāda 6** (Intelligence): Evolution adopts only verified fitness; dream cycle runs idle-only; dream produces hypotheses, never facts; hypotheses admitted (0, 1) not as knowledge; cheapest adequate tier chosen, not most eloquent; escalation is one step, second failure is jidoka.
- **Pāda 7** (Language): Utterances bind to shared vocabulary; REQUEST/PROPOSE carry intention; INFORM/ASSERT carry knowledge; ANDON names control action; canonical form bilingual (Sanskrit first, English companion); writing and reading roundtrip to original form.

The **27 Gītā verses** (from BG 2.47, 2.50, 3.35, 4.34, 6.5, 6.16, 6.17, 18.63, etc.) ground ethical and functional authority:
- **BG 2.47** ("karmaṇy evādhikāras te…"): Agents have authority over action, never verdict; agents never manufacture admission evidence.
- **BG 2.50** ("buddhiyukto jahātīha…"): Quality built into doing (jidoka), not inspected after.
- **BG 3.35** ("śreyān sva-dharmo…"): Disjoint ownership: each agent in its own scope, even imperfectly.
- **BG 18.63** ("iti te jñānam ākhyātaṃ…"): Full analysis offered; human choice to act remains.

**Validation**: `uos_swarm acl.gleam` validates every utterance against sūtra register and Gītā verse semantics; ACL `@sūtra S2.4` and `@gītā BG 2.47` headers on board messages; 49 sūtras + 27 verses rendered bilingually in the wiki.

### Music, Thaats, Rāgas, and Tālas

The **Hindustani musical system** provides organizational and observational structure:
- **10 Thaats ↔ 10 Layers (L0–L9)**: Bilawal (L0, all-shuddha major scale), Kalyan (L1, tivra-Ma), Khamaj (L2, komal-Ni), Bhairav (L3, komal-Re/Dha), Poorvi (L4), Marwa (L5), Kafi (L6, komal-Ga/Ni), Asavari (L7), Bhairavi (L8), Todi (L9).
- **7 Svara ↔ 7 Planes**: sa (नियन्त्रण control), re (संरचना structure), ga (प्रवर्तन runtime), ma (दत्तांश data), pa (सन्देश messaging), dha (बुद्धि intelligence), ni (भाषा language).
- **10 Rāgas**: Yaman, Bhairav, Bhairavi, Malkauns, Bilawal, Durga, Kafi, Todi, Marwa, Darbari Kanada — each with aroha/avaroha (ascent/descent), vadi (strong note), samvadi (companion), time-of-day, and mood.
- **6 Tālas**: Teentaal (तीनताल, 16 mātrā, 4|4|4|4 vibhāgs, sam=1, khālī=9, tālī at 1,5,13) as the audit heartbeat; Jhaptaal, Rupak, Ektaal, Keherwa, Dadra also mapped.

**In Code**: `uos_swarm raga.gleam` holds the 10 thaats and 10 rāgas; holon base rules bind dharma (function) and swara (pitch identity) to each holon. Manager keeps Teentaal: sam marks audit checkpoint, khālī post-processing gap, tālī pulse point. F´ channels carry Beat (mātrā) and Raga (aroha/avaroha).

**Saṅgīta** (music module): Bandish (composition) from board state with motif per message kind and octave per sender layer in Teentaal, sargam in IAST and Devanagari, pure-Gleam 16-bit WAV with just-intonation swaras. Harmony index from seven board measures. Prahar/rāga of hour. Growth gate: evolution never lowers harmony.

### Dream and Evolution

**Dream Module** (`uos_swarm dream.gleam`, `svapna`): Idle-only, deterministic hypothesis generation with confidence ∈ (0,1), basis message ids, eight hypothesis kinds (Rete inference, Bayes posterior, analogy, counterfactual, …), Yoga Sūtra 1.38 citation. Rendered as ACL `Hypothesize` utterance. Bounded by max hypotheses.

**Evolve Module** (`uos_swarm evolve.gleam`): Beta fitness updated only from non-empty evidence reference. Trialled ≥ 0.8 with ≥ 3 trials → Adopted; Rejected ≤ 0.2 from same evidence. Thompson selection reuses agent kernel's gamma sampler. Cheapest adequate tier picked. Evolve never decreases system harmony (wired into `record_in_harmony`).

**Agent Runtime Context**: `uos_swarm agent_runtime.gleam` carries Vritti (mind states), Antahkarana (cognitive stack), Guṇa (health classification), pramāṇa_of_evidence (knowledge source type).

### Cost Routing (R0–R6)

**Global Intelligence Routing** (`uos_swarm openrouter_worker.gleam`, `coord.route`): Six deterministic routing classes:
- **R0**: Runtime control (deterministic, 0 tokens). OODA, audits, reconciliation.
- **R1**: Mechanical verification (script, else Haiku). Tests, ownership checks.
- **R2**: Summaries & docs (Haiku or OpenRouter nano). Wiki sections, KPI tables.
- **R3**: Advisory second opinion (OpenRouter nano, ≤ USD 0.02, ≤ 512 tokens, 30 s, no private source).
- **R4**: Bounded implementation (Sonnet). One Gleam module + tests.
- **R5**: Sovereign review (Codex Astra + Antigravity, independent).
- **R6**: Design authority (Fable, policy-enforced). Plans, integration, admission.

Free tiers tried first when data policy allows. Escalation one step; second failure is jidoka. Adequacy posteriors per (tier, class) updated only from verified outcomes, never self-report. Every routing decision and outcome a board message (Dispatch/Report) so global spend per agent and class is visible in `usage` state.

### Board Alignment

The **message board** (`uos_swarm board.gleam`) validates every utterance through the system ontology:
- 14 message kinds drawn from `kind:*` ontology entries.
- 12 performative acts (Inform, Request, Propose, Accept, Reject, Query, Confirm, Commit, Assert, Retract, Hypothesize, Andon) validated against `perf:*` entries.
- Sūtra references (`@sūtra S2.4`, etc.) and Gītā verses (`@gītā BG 2.47`, etc.) validated against register.
- 33 board_agent ids (one per holon) validated; audit_subject id resolves to ontology entry.
- Lexicon (`uos_swarm acl.gleam lexicon`) enforces shared vocabulary.
- 3 explicit causal-gap records (S4.2) documented for reply targets known to be lost.
- 261/261 ontology entries aligned after round O integration.
- 194 valid messages on board; 0 warnings.

## Consequences

1. The unified ontology becomes the single source of truth for all semantic validation, CLI operations, ACL utterance parsing, and holonic structure.
2. Every agent on the hive (human operator, manager, worker, verifier) reasons within this shared framework; terms are unambiguous.
3. Sūtra and Gītā citations are not poetic but operational: they encode specific control laws and ethical constraints verified in code.
4. Music (rāga, tāla, svara) moves from metaphor to computational structure: harmony indices, Teentaal heartbeat, octave-per-layer bandish composition.
5. Dream and evolve become first-class hive capabilities: non-deterministic hypothesis generation (idle cycles) feeds evolution (verified outcomes).
6. Cost routing optimizes globally for cheapest adequate intelligence per operation class; no operation defaults to expensive tiers.
7. All three-hundred-plus system bindings (antaḥkaraṇa ↔ OODA, pramāṇa ↔ evidence sources, kośa ↔ layers, guṇa ↔ health) are now explicit in code, not implicit in documentation.
