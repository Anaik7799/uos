_Decision record (ADR) — captured in the Zettelkasten as part of the SDLC/SRE loop._

## Context (as-is)

To guarantee that high-level operational policies map isomorphically to hardware memory layouts without drift or unmapped orphan components, the Unified Operational System is formalized across seven levels of fractal granularity with 100% functional mapping KPIs across all 11 planes.

## Decision (to-be)

Formally adopt the Seven-Level Fractal Granularity Taxonomy (Level 1 Mesh Topology down to Level 7 Machine/Memory Layout) and enforce 100% functional mapping KPIs across SDLC, SRE, Control, Data, Evidence, Runtime, Formal, AI/ML, Skills, SOPs, and Superpowers.

## Agent reasoning

Formalizing the architecture across 7 levels of granularity prevents abstraction leakage and guarantees end-to-end mathematical verification: proofs at Level 5 govern contracts at Level 4, which enforce schemas at Level 6, which map directly to arena layouts at Level 7.

## Criteria · Architecture

Seven levels of granularity encompassing dual-host Tailnet mesh (L1), 12 pillars (L2), BEAM supervision trees (L3), C-ABI/Gospel contracts (L4), Lean 4/Rocq theorems (L5), 18-table WAL SQLite schemas (L6), and Zig term arena layouts (L7).

## Criteria · Test

100% KPI mapping across all 184 system facets, 9,767 Gleam tests passing, all 6 local HTTP endpoints and 4 remote Tailnet endpoints returning 200 OK.

## Criteria · Docs

Documented in 2026-09-04-unified-operational-system-design-plan.md (Section 29), 2026-09-04-claude-codex-review-dossier.md (Section 15), and 2026-09-04-source-backed-operational-catalogue.md (Section 7).

## Tradeoffs

Requires rigorous compliance checks at all 7 levels for any code modification; completely eliminates operational drift and silent regressions.

## Alternatives — what else could be done

Loose hierarchical grouping without explicit 7-level mathematical mapping allowed unverified gaps between high-level documentation and low-level C-ABI code.
