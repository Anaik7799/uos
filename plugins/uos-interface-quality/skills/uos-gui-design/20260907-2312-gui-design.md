Use the repository's Lustre/Wisp components and existing design tokens. Preserve the product's visual language. Read [interface rules](../../references/20260907-2312-interface-rules.md) sections GUI and Shared; they are sufficient without global skills.

1. Identify the operator's next decision. Establish page hierarchy, primary action, reading order and information density before styling. Group related metrics; use progressive disclosure for detail.
2. Model loading, empty, ready, stale, disconnected and failed states explicitly. Separate user intent, pending execution and observed result.
3. Prefer semantic HTML and typed Lustre events. Keep Model/Msg/update pure; perform network and persistence effects at existing supervised boundaries. A renderer alone does not create a running MVU application.
4. Specify typography, spacing, contrast and responsive behavior using current tokens. Check keyboard focus, accessible names and zoom/reflow. Use text with status colors, and respect reduced-motion preferences.
5. Bind live data to source timestamps and validity bounds. For SSE, verify the deployed route, content type, event names, reconnect behavior and actual visible updates. Render external message text safely.
6. Verify the changed behavior, then inspect representative viewport and keyboard states. State exactly which browser, accessibility and deployment checks ran. Apply scenarios UI-01–04 and UI-08–09; missing tools mean UNRUN for those checks.

Use [UI workflow](../uos-ui-superpowers/SKILL.md) for design decisions, debugging and completion evidence. This skill authorizes no installation, deployment or unrelated redesign.
