Read [interface rules](../../references/20260907-2312-interface-rules.md) sections TUI and Shared. Reuse UOS terminal abstractions; evaluate alternative frameworks as reference material before adding a dependency.

1. Locate the runnable terminal entrypoint, input decoder, update loop and renderer. Confirm navigation reaches the view. A nonempty rendered string is not an interactive TUI.
2. Design discoverable shortcuts, help, focus, selection and scrolling. Separate navigation keys from text entry; prevent pasted text from becoming commands. Keep critical status and exit controls reachable in a small terminal.
3. Keep domain transitions typed and pure in Gleam; supervise terminal and backend I/O. Present pending, denied, failed and confirmed actions according to real executor receipts.
4. Separate trusted styling from external text. Neutralize injected control sequences, handle grapheme boundaries and terminal-cell widths, and provide a plain/colorless mode.
5. Bound input buffers, event queues, history and repaint rate. Preserve selection and clear stale regions on resize. Handle partial escape sequences, EOF, catchable signals and suspend/resume; restore raw mode, cursor and alternate screen.
6. Use a private PTY test for key sequences, resize, Unicode, malformed input and terminal cleanup. Run scenarios UI-05–07 and UI-09–10. If PTY testing is unavailable, report it as UNRUN rather than infer success from string snapshots.

Use [UI workflow](../uos-ui-superpowers/SKILL.md). No skill installation grants permission to control services or launch peers.
